# RB-008: Detector blind or heartbeat missing

## Symptoms
The "Guardian is blind" alert fires because the detector job failed twice in a row, or the missing-heartbeat alert fires because no heartbeat arrived for 24 hours. No new samples appear in Postgres. While this lasts, the fleet is not being watched by the agent.

## Diagnosis
Check the detector's Container Apps Job execution history and its logs for the failed runs. Common causes: the managed identity lost its role on the scale set or the Log Analytics workspace, a Log Analytics query that now errors or times out, Postgres unreachable or out of storage, an expired secret in Key Vault, or the job's cron schedule disabled. Run the detector's KQL query by hand to see whether it returns data.

## Allowed actions
None automatic. The agent cannot repair its own monitoring, because the part that is broken is the part that would check the fix. Page a human (Critical) with the job's error output and the time of the last good sample. The baseline protections (log retention task, automatic instance repairs, disk-free alert) keep running without the agent and cover the most common failures in the meantime.

## Rollback
No action is taken, so there is nothing to roll back. After a human fixes the cause, confirm two successful detector runs in a row and a fresh heartbeat before closing the incident.
