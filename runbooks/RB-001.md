# RB-001: Disk filling from IIS logs, temp files or crash dumps

## Symptoms
C: drive above 90% used, or growing fast enough to fill within 12 hours. Site may return 500 errors or stop writing logs. Event log may show disk-space warnings (Event ID 2013).

## Diagnosis
Check the size of C:\inetpub\logs\LogFiles, C:\Windows\Temp, the user temp folders and C:\ProgramData\Microsoft\Windows\WER. Compare the oldest log date with the retention policy (7 days). If these folders explain most of the growth, this runbook applies. If not, use RB-002.

## Allowed actions
Tier 0, automatic: delete_iis_logs_older_than(days=7), clear_temp, clear_wer_dumps. Always dry-run first and check the file list and hash. Never delete outside these folders.

## Rollback
Deleted logs cannot be restored unless archived. If logs must be kept, archive to Blob Storage before deleting. Confirm free space recovered after the action; if not, escalate.
