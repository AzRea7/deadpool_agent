# RB-010: Linux disk filling from an unknown consumer or deleted-but-open files
Platform: linux

## Symptoms
The root filesystem (/) is above 90% used, or projected full within 12 hours, but the folders covered by RB-009 (Apache logs, the journal, package caches, /tmp) are small or already cleaned. Growth continues after the RB-009 cleanup runs. A common sign: `df` reports much more used space than `du` can account for.

## Diagnosis
Find the largest directories without crossing filesystems: `du -xh --max-depth=2 / 2>/dev/null | sort -h | tail -20`. If `df` and `du` disagree by gigabytes, a process is holding a deleted file open, often a log someone removed with `rm` while Apache still writes to it: list them with `lsof +L1` (or `find /proc/*/fd -lname '*(deleted)'`) and note the process and size. Other common causes: core dumps in /var/crash or /var/lib/systemd/coredump, an application writing uploads or logs inside the site directory, Docker images and overlay layers under /var/lib/docker, and old kernels in /boot. Also check inodes with `df -i`: a filesystem can be "full" with free bytes if millions of small files used every inode. Compare the growth start time with recent deploys and configuration changes.

## Allowed actions
Propose only, with one exception. If the space is held by deleted-but-open log files and the process is Apache, Tier 1 graceful_reload_service(apache2) on the affected instance makes Apache reopen its logs and releases the space (at most once per instance per hour, canary first). Anything else is a proposal: the folder or process, its size, its growth rate, the likely owner and the suggested fix. Any deletion outside the RB-009 allowlist is Tier 2 (delete_paths) and needs human approval with the dry-run file list.

## Rollback
A graceful reload finishes in-flight requests and changes no files. No other automatic action is taken. If a human approves a deletion, it must follow a dry run with the exact file list and hash, and anything that might be needed later is archived to Blob Storage first. If the disk reaches 95% before a human responds, stop and page (Critical).
