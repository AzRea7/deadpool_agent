# RB-011: Apache down, crashing or out of workers
Platform: linux

## Symptoms
The site on one instance returns 503 Service Unavailable, refuses connections, or requests hang until the client times out. The health probe fails 3 times in 5 minutes on that instance while others stay healthy. A crash or stopped service usually shows as connection refused straight away. Worker exhaustion usually shows as slow responses and timeouts while the service still reports active.

## Diagnosis
Check the unit: `systemctl status apache2` (httpd on RHEL) for active, failed or activating, and `journalctl -u apache2 --since "-1h"` for why it stopped. Read the Apache error log (/var/log/apache2/error.log): "AH00161: server reached MaxRequestWorkers setting" means every worker is busy (overload or a slow backend), "AH00052: child pid ... exit signal Segmentation fault" means children are crashing, "AH00526: Syntax error" or "AH00072: make_sock: could not bind to address" means it cannot start (config or port conflict, run `apachectl configtest`). With mod_status enabled, `/server-status?auto` shows BusyWorkers against the limit. If the kernel log shows the OOM killer ending Apache processes, use RB-012 instead. If the failures started right after a deploy and affect every instance, use RB-005.

## Allowed actions
Tier 1, automatic with limits: restart_service(apache2) when the unit is failed or inactive, or graceful_reload_service(apache2) when it is active but out of workers. Affected instance only, at most once per instance per hour, canary first, and only service names on the allowlist. Never restart every instance at once. Do not restart when `apachectl configtest` fails: a restart will not come back, so escalate with the syntax error. Verify after 2 minutes: the unit is active, the health probe passes 3 times in a row and the 503 rate is back to baseline.

## Rollback
A restart or reload changes no files or settings. Side effects: requests in flight are dropped by a restart (a graceful reload lets them finish) and sessions held in Apache child memory are lost. If Apache fails again within the hour, do not restart again: escalate with the unit status, the error log lines above and the time of the last deploy. Raising MaxRequestWorkers is a configuration change and therefore a Tier 2 proposal.
