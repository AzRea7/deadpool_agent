# RB-007: Instance unreachable or unhealthy
Platform: any

## Symptoms
One instance stops answering entirely: the health probe fails, no new metrics or heartbeat arrive from it, and Run Command times out. The scale set may show the instance as unhealthy or not running.

## Diagnosis
Check the instance view: `az vmss get-instance-view --resource-group <rg> --name <vmss> --instance-id <id>` for its power state and provisioning state. Look at boot diagnostics (the screenshot and serial log) for a stuck boot, a blue screen (Windows) or kernel panic and emergency-mode shell (Linux), or an update in progress. Check whether the instance is mid-upgrade or being removed by scale-in, and skip it if so. Check whether the scale set's automatic instance repairs have already started a repair, so the agent does not act on top of it.

## Allowed actions
Tier 2, human approval required: reimage_instance(id), or scale_out to add capacity while the instance is investigated. The agent never reimages on its own. It proposes the action with the evidence (instance view, boot diagnostics, last heartbeat time) and pauses for approval with the approver ID and plan hash. If automatic instance repairs is already handling it, the agent only reports.

## Rollback
A reimage replaces the OS disk with a fresh copy of the image. Anything stored only on the OS disk is lost, including web server logs that were not shipped to Log Analytics; the data disk is kept. There is no undo, which is why this is Tier 2. Verify after the reimage that the instance reports healthy and the health probe passes. If it fails again, escalate (Critical) and consider removing the instance from the scale set.
