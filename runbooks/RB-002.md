# RB-002: Disk filling from an unknown consumer
Platform: windows

## Symptoms
C: drive above 90% used, or projected full within 12 hours, but the folders covered by RB-001 (IIS logs, temp, WER dumps) are small or already within retention. Growth continues after the RB-001 cleanup runs.

## Diagnosis
Find the largest folders on C:, starting from the top level and drilling down: `Get-ChildItem C:\ -Directory -Force -ErrorAction SilentlyContinue | ForEach-Object { [pscustomobject]@{ Path = $_.FullName; GB = [math]::Round((Get-ChildItem $_.FullName -Recurse -File -Force -ErrorAction SilentlyContinue | Measure-Object Length -Sum).Sum / 1GB, 2) } } | Sort-Object GB -Descending`. Common causes: Failed Request Tracing left switched on (C:\inetpub\logs\FailedReqLogFiles), an application writing its own logs or uploads inside the site folder, Windows Update cache (C:\Windows\SoftwareDistribution), a large pagefile.sys or hiberfil.sys, and leftover installers or backups. Compare the growth start time with recent deploys and configuration changes. Never treat C:\Windows\WinSxS as safe to delete by hand.

## Allowed actions
Propose only. Nothing outside the RB-001 allowlist is deleted automatically. The agent writes a proposal: the folder, its size, its growth rate, the likely owner and the suggested fix (for example, switch off Failed Request Tracing, move application logs to the data disk, or add the folder to a retention policy). Any deletion outside the allowlist is Tier 2 (delete_paths) and needs human approval with the dry-run file list.

## Rollback
No automatic action is taken, so there is nothing to roll back. If a human approves a deletion, it must follow a dry run with the exact file list and hash, and anything that might be needed later is archived to Blob Storage first. If the disk reaches 95% before a human responds, stop and page (Critical).
