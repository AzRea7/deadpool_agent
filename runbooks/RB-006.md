# RB-006: IIS service stopped (W3SVC or WAS)

## Symptoms
Every site on one instance fails at once: connections are refused or every request returns 503. The health probe fails on that instance. App pools cannot be started because the services they depend on are not running.

## Diagnosis
Check both services: `Get-Service W3SVC, WAS | Select-Object Name, Status`. W3SVC (World Wide Web Publishing Service) depends on WAS (Windows Process Activation Service), so a stopped WAS also stops W3SVC. In the System event log, look for 7031 or 7034 (service terminated unexpectedly) and 7036 (service changed state) to see whether it crashed or someone stopped it. Check for a pending reboot or an in-progress Windows Update, which can stop these services on purpose. If the services are running but one pool is down, use RB-003.

## Allowed actions
Tier 1, automatic with limits: restart_service(WAS), then restart_service(W3SVC), on the affected instance only. At most once per instance per hour, canary first, and only service names on the allowlist. Skip the action if the instance is mid-update or mid scale-in. Verify after 2 minutes that both services show Running and the health probe passes 3 times in a row.

## Rollback
Starting a service changes no files or settings, so there is nothing to undo. If the service stops again within the hour, do not restart it again: escalate with the 7031/7034/7036 events and the update status. If the instance cannot be reached to run the action, use RB-007.
